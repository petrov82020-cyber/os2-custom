🛡️ Введение: полное руководство по UpdraftPlus

✍️ Время чтения: ~35 минут | 🎯 Цель: освоить UpdraftPlus от установки до восстановления резервной копии на тестовом сайте
💡 Что вы узнаете:
Этот материал — практическое дополнение к курсу о восстановлении сайта. Здесь мы подробно, шаг за шагом, разберём самый популярный плагин для резервного копирования WordPress — UpdraftPlus. Вы научитесь делать правильные бэкапы, настраивать автоматическое расписание, хранить копии в облаке и — самое главное — восстанавливать сайт из копии. Каждый шаг проиллюстрирован и снабжён практическими советами.

Сайт WordPress — это не только папка с файлами. Вся динамика хранится в базе данных MySQL: записи, страницы, комментарии, пользователи, заказы. Если сделать копию только файлов — при восстановлении вы получите «пустой» сайт с шаблоном, но без контента. Если сделать копию только базы — потеряете тему, плагины, изображения. Поэтому правильный бэкап всегда включает две части. UpdraftPlus — плагин, который делает это автоматически.

Почему без резервных копий не обойтись

Сайты «рушатся» по разным причинам. По статистике, каждый пятый владелец WordPress хотя бы раз в год терял сайт или данные. Вот основные сценарии:

💥
Сбой после обновления Обновление плагина, темы или WordPress «убило» сайт. Без бэкапа придётся вручную разбираться с ошибками.
🔓
Взлом сайта Хакеры удалили или изменили файлы. Восстановление возможно только из чистого бэкапа.
🖥️
Сбой хостинга Сервер вышел из строя, произошла миграция. Без своей копии вы зависите от хостера.
✋
Случайное удаление Вы или сотрудник случайно удалили важную страницу, товар или всю базу данных.
🐛
Ошибка в коде Одна опечатка в functions.php — и сайт показывает «белый экран». Бэкап вернёт всё за минуту.
🌐
Проблемы с доменом Истёк срок регистрации, изменились DNS. Даже после восстановления домена контент может быть повреждён.
⚠️ Главное правило веб-мастера:
«Нет бэкапа — нет изменений». Никогда не начинайте обновление, правку кода или установку плагина, если у вас нет свежей резервной копии. Это правило спасло тысячи сайтов.

Что такое UpdraftPlus и почему именно он

UpdraftPlus — самый популярный плагин для резервного копирования WordPress. Более 3 миллионов активных установок. Он делает полные копии сайта (файлы + база данных), хранит их в облаке и позволяет восстановить сайт в один клик.

✅ Преимущества UpdraftPlus

  • Бесплатный — все базовые функции доступны без оплаты.
  • Автоматизация — бэкапы по расписанию без вашего участия.
  • 8 облачных хранилищ — Google Drive, Dropbox, OneDrive, S3, FTP, SFTP, WebDAV, email.
  • Раздельные расписания — отдельно для файлов, отдельно для базы данных.
  • Восстановление в один клик — без FTP и phpMyAdmin.
  • Миграция сайта — можно перенести сайт на другой хостинг.
  • Email-отчёты — уведомления о каждом бэкапе.
  • Ограничение копий — старые удаляются автоматически.

⚠️ Ограничения бесплатной версии

  • Нет инкрементальных бэкапов (каждый раз копируется всё).
  • Нет бэкапов по событию (например, перед обновлением).
  • Нет шифрования резервных копий.
  • Нет восстановления отдельных файлов.
  • Нет приоритетной поддержки.

Для 95% сайтов бесплатной версии более чем достаточно.

Шаг 1. Установка UpdraftPlus

Установка плагина занимает 2 минуты и не требует специальных знаний.

  1. Войдите в админ-панель WordPress. Откройте https://ваш_домен/wp-admin.
  2. Перейдите в «Плагины → Добавить новый».
  3. В строке поиска введите UpdraftPlus.
  4. Найдите плагин «UpdraftPlus WordPress Backup Plugin». Убедитесь, что автор — UpdraftPlus.Com, DavidAnderson.
  5. Нажмите «Установить сейчас».
  6. После установки нажмите «Активировать».
  7. В левом меню появится пункт «UpdraftPlus». Плагин готов к работе.
✅ Готово! UpdraftPlus установлен и активирован. Теперь можно приступить к настройке.

Шаг 2. Первый бэкап: файлы и база данных

Первый бэкап обязательно делайте вручную — так вы убедитесь, что всё работает. Автоматизацию настроим позже.

💡 Почему важно копировать и файлы, и базу:
  • Файлы: тема, плагины, изображения, загрузки, wp-config.php.
  • База данных: записи, страницы, настройки, пользователи, комментарии.
Обе части критически важны. Восстановление только одной из них даст неполный результат.

Пошаговая инструкция

  1. Откройте «UpdraftPlus → Резервное копирование / Восстановление» (Backup / Restore).
  2. Нажмите большую кнопку «Резервное копирование сейчас» (Backup Now).
  3. Откроется модальное окно с опциями. Убедитесь, что отмечены:
    • ✅ Include your database in the backup (включить базу данных).
    • ✅ Include your files in the backup (включить файлы).
  4. Нажмите «Резервное копирование сейчас».
  5. Наблюдайте за процессом. Прогресс-бар покажет этапы:
    • Создание дампа базы данных.
    • Копирование файлов.
    • Загрузка в облако (если настроено).
  6. Дождитесь завершения. Обычно это занимает 2–10 минут в зависимости от размера сайта.
  7. Проверьте результат. Список существующих бэкапов появится внизу страницы.
⚠️ Если бэкап завис или не завершился:
  • Проверьте, хватает ли места на хостинге.
  • Увеличьте лимит памяти PHP (memory_limit) до 256 МБ.
  • Увеличьте максимальное время выполнения скрипта (max_execution_time) до 300 секунд.
  • Разбейте бэкап: сначала только база, потом только файлы.

Шаг 3. Настройка отдельных расписаний

База данных меняется гораздо чаще, чем файлы. Каждая публикация, комментарий, заказ или регистрация — это изменение в базе. Файлы (тема, плагины, изображения) обновляются реже. Поэтому разумно делать для них разные расписания.

Пошаговая инструкция

  1. Откройте «UpdraftPlus → Настройки» (Settings).
  2. Найдите раздел «Расписания резервного копирования файлов и базы данных» (Files and Database Backup Schedules).
  3. Настройте расписание для файлов:
    • Files backup schedule: выберите частоту (например, Weekly — еженедельно).
    • First backup: укажите, когда сделать первый бэкап.
  4. Настройте расписание для базы данных:
    • Database backup schedule: выберите частоту (например, Daily — ежедневно).
    • First backup: укажите, когда сделать первый бэкап.
  5. Нажмите «Сохранить изменения» (Save Changes).

💡 Бонус: Делайте ручную резервную копию перед каждым обновлением WordPress, темы или плагинов. Это самая частая причина поломок. Если что-то пойдёт не так, вы сможете откатиться к состоянию «за минуту до обновления».

Шаг 4. Ограничение количества хранимых копий

Если не ограничивать количество, резервные копии быстро займут всё доступное место. UpdraftPlus умеет автоматически удалять самые старые копии при появлении новых.

Пошаговая инструкция

  1. Откройте «UpdraftPlus → Настройки».
  2. Найдите раздел «Хранить столько запланированных резервных копий» (Retain this many scheduled backups).
  3. Укажите число. Рекомендую:
    • Файлы: 4 копии.
    • База данных: 8–14 копий (база меньше по размеру, можно хранить больше).
  4. Нажмите «Сохранить изменения».
⚠️ Не ставьте слишком мало копий!
Не ограничивайтесь 1 копией. Лучше иметь 3–5 файловых и 8–14 базовых копий, чтобы была возможность откатиться на несколько шагов назад, если проблема обнаружится не сразу.

Шаг 5. Включение email-отчётов

Автоматическое резервное копирование может незаметно сломаться. Например, закончится место, изменится пароль к облаку или произойдёт сбой на сервере. Email-отчёты позволяют вовремя заметить проблему.

Пошаговая инструкция

  1. Откройте «UpdraftPlus → Настройки».
  2. Найдите опцию «Получать уведомления о резервном копировании по email» (Get backup notification by email).
  3. Включите её.
  4. Укажите email. По умолчанию — email администратора сайта.
  5. Нажмите «Сохранить изменения».
💡 Совет: Проверьте, что письма не попадают в спам. Добавьте адрес отправителя (no-reply@ваш_домен) в белый список вашей почты.

Шаг 6. Хранение копий вне сервера

Если резервные копии лежат на том же сервере, что и сайт, вы потеряете и то, и другое при аварии сервера, взломе или отключении хостинга. Отправьте копию в облако.

Пошаговая инструкция (на примере Google Drive)

  1. Откройте «UpdraftPlus → Настройки».
  2. Прокрутите до раздела «Удалённое хранилище» (Remote storage).
  3. В выпадающем списке выберите Google Drive.
  4. Нажмите «Авторизоваться в Google Drive».
  5. Войдите в свой Google-аккаунт. Разрешите доступ для UpdraftPlus.
  6. Скопируйте код авторизации и вставьте его в поле.
  7. Выберите папку для сохранения бэкапов. Рекомендую создать отдельную папку «Бэкапы сайта».
  8. Нажмите «Сохранить изменения».
  9. Проверьте соединение: нажмите «Тест удалённого хранилища» (Test Remote Storage).
✅ Готово! Теперь копии будут автоматически загружаться в Google Drive. Если сайт «упадёт» — у вас останется резервная копия в облаке.

Шаг 7. Проверка восстановления на тестовом сайте

Резервная копия бесполезна, если её нельзя восстановить. Многие узнают об этом только в критический момент. Поэтому нужно заранее протестировать восстановление на отдельном сайте.

Способ 1: Восстановление на локальном сайте

Если у вас есть локальный WordPress (например, через Local by Flywheel или XAMPP), используйте его как тестовый.

  1. Скачайте резервную копию из UpdraftPlus:
    • Откройте «UpdraftPlus → Резервное копирование / Восстановление».
    • Прокрутите до раздела «Существующие резервные копии» (Existing backups).
    • Найдите нужный бэкап.
    • Скачайте все компоненты: database, plugins, themes, uploads, others.
  2. На локальном сайте установите чистый WordPress.
  3. Установите и активируйте UpdraftPlus.
  4. Загрузите скачанные файлы:
    • Откройте «UpdraftPlus → Резервное копирование / Восстановление».
    • Нажмите «Загрузить резервные копии» (Upload backup files).
    • Загрузите все скачанные файлы.
  5. Восстановите сайт:
    • Рядом с загруженными файлами нажмите «Восстановить» (Restore).
    • Отметьте все компоненты для восстановления.
    • Нажмите «Восстановить».
  6. Проверьте результат. Сайт должен открыться с тем же контентом, что был в момент бэкапа.

Способ 2: Восстановление на отдельном поддомене

Если локального сайта нет, создайте поддомен на хостинге (например, test.ваш_сайт.ru) и используйте его как тестовый.

  1. Создайте поддомен в панели хостинга.
  2. Установите на него чистый WordPress.
  3. Установите UpdraftPlus.
  4. Загрузите и восстановите бэкап по инструкции выше.
  5. Проверьте результат.
  6. Удалите тестовый сайт, когда закончите.
⚠️ Если бэкап не восстанавливается:
Возможные причины:
  • Архив повреждён — попробуйте другую копию.
  • Не хватает памяти — увеличьте memory_limit.
  • Таймаут выполнения — увеличьте max_execution_time.
  • Проблемы с правами доступа — установите 755 на папки.

Восстановление сайта из резервной копии: пошаговый алгоритм

Когда сайт «упал» и нужна срочная реставрация, действуйте по этому алгоритму.

Шаг 1: Определите, что сломалось Белый экран? Ошибка 500? Пустой сайт? Странный контент? Запишите симптом.
Шаг 2: Попробуйте войти в админку Открывается ли /wp-admin? Если да — восстановление через UpdraftPlus в один клик. Если нет — через FTP.
Шаг 3: Откройте UpdraftPlus → Резервное копирование / Восстановление Найдите самый свежий рабочий бэкап. Убедитесь, что в нём есть файлы и база данных.
Шаг 4: Нажмите «Восстановить» (Restore) Отметьте все компоненты: database, plugins, themes, uploads, others.
Шаг 5: Дождитесь завершения Процесс может занять 5–30 минут в зависимости от размера сайта.
Шаг 6: Проверьте сайт Откройте главную, страницы, записи, медиафайлы, формы. Убедитесь, что всё работает.
Шаг 7: Если что-то не работает Попробуйте более старый бэкап. Проверьте wp-config.php, .htaccess. Обратитесь в поддержку хостинга.

Восстановление через FTP: если админка не работает

Если сайт «упал» так, что админка недоступна, восстановление делается через FTP и phpMyAdmin.

  1. Скачайте резервную копию из облака (Google Drive, Dropbox).
  2. Распакуйте архивы на компьютере:
    • uploads — в wp-content/uploads/.
    • themes — в wp-content/themes/.
    • plugins — в wp-content/plugins/.
    • others — wp-config.php, .htaccess.
    • database.sql — дамп базы.
  3. Подключитесь к сайту по FTP.
  4. Переименуйте текущую папку wp-content в wp-content_broken.
  5. Загрузите распакованную папку wp-content из бэкапа.
  6. Загрузите wp-config.php и .htaccess из бэкапа.
  7. Восстановите базу данных:
    • Откройте phpMyAdmin.
    • Выберите базу данных.
    • Вкладка «Импорт».
    • Загрузите database.sql.
    • Нажмите «Импорт».
  8. Проверьте wp-config.php: DB_NAME, DB_USER, DB_PASSWORD, DB_HOST должны соответствовать текущей базе.
  9. Откройте сайт. Если всё в порядке — восстановление завершено.
💡 Если база данных повреждена, но не утрачена:
В phpMyAdmin нажмите «Проверить» (Check) — увидите повреждённые таблицы. Затем «Восстановить» (Repair) — phpMyAdmin попробует их исправить.

Восстановление не работает Неполный бэкап или несовместимость версий Проверьте, все ли компоненты скачаны. Попробуйте более старую копию
После восстановления сайт «пустой» Восстановлены только файлы или только база Восстановите обе части: сначала база, потом файлы (или наоборот)
Сайт показывает ошибку после восстановления Неверные данные в wp-config.php Проверьте DB_NAME, DB_USER, DB_PASSWORD, DB_HOST
Бэкап слишком долго создаётся Большой сайт или медленный хостинг Разбейте бэкап: отдельно база, отдельно файлы. Используйте инкрементальные копии (Pro)

Практическое задание

📝 Задание: настройте UpdraftPlus с нуля

Часть 1: Установка
1. Установите и активируйте UpdraftPlus.
2. Откройте «UpdraftPlus → Резервное копирование / Восстановление».

Часть 2: Первый бэкап
3. Нажмите «Резервное копирование сейчас».
4. Убедитесь, что отмечены файлы и база данных.
5. Дождитесь завершения.
6. Проверьте, что бэкап создан.

Часть 3: Настройка расписаний
7. Откройте «UpdraftPlus → Настройки».
8. Настройте расписание для файлов (например, Weekly).
9. Настройте расписание для базы (например, Daily).
10. Ограничьте количество копий (4 файловых, 8 БД).
11. Включите email-отчёты.
12. Сохраните настройки.

Часть 4: Облачное хранилище
13. В разделе «Удалённое хранилище» выберите Google Drive.
14. Авторизуйте аккаунт.
15. Выберите папку для бэкапов.
16. Сохраните и проверьте соединение.
17. Создайте новый бэкап — он должен загрузиться в облако.

Часть 5: Проверка восстановления
18. Скачайте один из бэкапов на компьютер.
19. Распакуйте архивы.
20. Убедитесь, что внутри есть файлы и .sql-дамп базы.
21. Если есть тестовый сайт — восстановите на нём бэкап.
22. Если нет — проверьте целостность архивов.

Часть 6: Создание привычки
23. Перед следующим обновлением WordPress сделайте ручной бэкап.
24. Обновите WordPress.
25. Если всё работает — удалите ручную копию через 2–3 дня.
26. Если что-то сломалось — восстановите из неё.
