Глава 2: Структура файлов WordPress — что где лежит

✍️ Время чтения: ~28 минут | 🎯 Цель: изучить файловую систему WordPress и научиться находить нужные файлы для правки, бэкапа и восстановления

Прежде чем править код, подключаться по FTP или восстанавливать сайт, нужно чётко понимать, где что лежит. WordPress имеет стройную файловую структуру, и знание её — основа всех дальнейших действий. В этой главе мы разберём каждую папку и каждый важный файл: что в них находится, за что они отвечают и когда их нужно трогать.

💡 Зачем это нужно:
Когда сайт «упадёт», вы будете знать, какой файл править. Когда нужно сделать бэкап — поймёте, что копировать. Когда нужно добавить стиль — найдёте куда вставить. Без знания структуры любая правка превращается в угадайку.

2.1 Общая картина файловой системы WordPress

WordPress имеет модульную структуру. Файлы разделены на три большие группы:

  • Ядро WordPress — файлы самой системы. Их не трогают, они обновляются автоматически.
  • Контент — темы, плагины, загруженные файлы. Это ваша зона ответственности.
  • Конфигурация — файлы настроек, отвечающие за подключение к базе данных и работу сайта.

Вот как выглядит типичная структура WordPress:

📁 public_html/ ← корень сайта (может называться htdocs, www и т. д.) │ ├── 📁 wp-admin/ ← файлы админ-панели (не трогать) ├── 📁 wp-includes/ ← библиотеки ядра (не трогать) │ ├── 📁 wp-content/ ← ВАША ЗОНА: темы, плагины, загрузки │ ├── 📁 themes/ ← установленные темы │ │ ├── 📁 twenty-twenty-five/ │ │ ├── 📁 my-child-theme/ │ │ └── ... │ ├── 📁 plugins/ ← установленные плагины │ │ ├── 📁 akismet/ │ │ ├── 📁 contact-form-7/ │ │ └── ... │ ├── 📁 uploads/ ← все загруженные файлы (изображения, PDF) │ │ └── 📁 2026/ │ │ └── 📁 10/ │ ├── 📁 mu-plugins/ ← обязательные плагины │ ├── 📁 upgrade/ ← временные файлы обновлений │ └── 📁 cache/ ← кэш (если есть) │ ├── 📄 wp-config.php ← КРИТИЧЕСКИ ВАЖНЫЙ файл настроек ├── 📄 .htaccess ← правила сервера (ЧПУ, редиректы, безопасность) ├── 📄 index.php ← точка входа ├── 📄 wp-load.php ← загрузчик ├── 📄 wp-settings.php ← инициализация └── ... (другие файлы ядра)
⚠️ Главное правило: Никогда не правьте файлы в wp-admin/ и wp-includes/. Это ядро WordPress. Любые изменения будут перезаписаны при следующем обновлении. Все правки делаются только в wp-content/ или в конфигурационных файлах.

2.2 wp-content — ваша зона ответственности

Папка wp-content/ — это сердце вашего сайта. Здесь хранится всё, что вы создаёте и устанавливаете. Разберём её содержимое подробно.

🎨
themes/ — темы Все установленные темы. Активная тема определяет внешний вид сайта. Здесь правят CSS, шаблоны, функции.
🔌
plugins/ — плагины Все установленные плагины. Каждый плагин — отдельная папка. Здесь можно найти проблемный плагин и отключить его.
🖼️
uploads/ — загрузки Все загруженные файлы: изображения, PDF, видео. Файлы автоматически разбиваются по годам и месяцам.
📌
mu-plugins/ — обязательные плагины Плагины из этой папки загружаются автоматически и не могут быть отключены через админку. Используются хостингами.
⚡
cache/ — кэш Кэш-файлы, создаваемые плагинами кэширования. Можно безопасно очищать — они пересоздадутся автоматически.
⬆️
upgrade/ — обновления Временная папка для обновлений. Если обновление зависло — можно очистить вручную.

Папка themes/ — самое важное место для кастомизации

Активная тема — это та, чьи файлы определяют внешний вид вашего сайта. Внутри папки темы есть ключевые файлы:

📁 twenty-twenty-five/ ← папка темы │ ├── 📄 style.css ← главный CSS-файл темы ├── 📄 functions.php ← функции темы (сюда добавляют код) ├── 📄 theme.json ← глобальные стили для блочных тем ├── 📄 index.php ← основной шаблон ├── 📄 screenshot.png ← превью темы в админке │ ├── 📁 templates/ ← HTML-шаблоны (для блочных тем) ├── 📁 parts/ ← части шаблона (шапка, подвал) ├── 📁 patterns/ ← паттерны темы ├── 📁 styles/ ← стилевые вариации ├── 📁 assets/ ← изображения, шрифты, JS └── 📁 inc/ ← дополнительные PHP-файлы
💡 Ключевые файлы темы:
  • style.css — основной файл стилей. В нём содержится информация о теме (название, автор, версия) и все CSS-правила.
  • functions.php — «мозг» темы. Здесь добавляют собственные функции, подключают скрипты, стили, регистрируют меню и виджеты.
  • theme.json — конфигурация глобальных стилей для блочных тем. Здесь задаются цвета, шрифты, макет.
⚠️ Не правьте файлы темы напрямую! Любые изменения в style.css или functions.php исчезнут при обновлении темы. Используйте дочернюю тему (глава 7) или «Дополнительные CSS» (глава 6).

Папка plugins/ — где искать виновника проблем

Каждый плагин — отдельная папка. Когда сайт «ломается» после установки плагина, вы можете найти его папку здесь и временно переименовать — это мгновенно отключит плагин.

Пример: если сайт упал после установки плагина contact-form-7, переименуйте папку:

📁 plugins/contact-form-7/   →   📁 plugins/contact-form-7_off/

Сайт сразу заработает — плагин отключится, потому что WordPress не найдёт его папку. Это спасает, когда админка недоступна.

Папка uploads/ — все медиафайлы

Здесь хранятся все файлы, загруженные через медиабиблиотеку. Структура автоматическая:

📁 uploads/
├── 📁 2024/
│   ├── 📁 01/  (январь)
│   ├── 📁 02/  (февраль)
│   └── ...
├── 📁 2025/
│   └── ...
└── 📁 2026/
    └── 📁 10/
        ├── image1.jpg
        ├── image1-150x150.jpg  (миниатюра)
        ├── image1-300x200.jpg  (средний размер)
        └── image1-1024x768.jpg (большой размер)

WordPress автоматически создаёт несколько версий каждого изображения (миниатюры, средние, большие). Это важно знать при резервном копировании: папка uploads/ может занимать гигабайты.

2.3 Конфигурационные файлы — самое важное

Три файла в корне сайта критически важны. Понимание их роли спасёт вас при восстановлении.

wp-config.php — мозг сайта

Это самый важный файл WordPress. Здесь хранятся:

  • Данные подключения к базе данных: имя БД, пользователь, пароль, хост.
  • Префикс таблиц (обычно wp_).
  • Секретные ключи для шифрования cookie.
  • Настройки отладки (режим debug).
  • Память PHP: WP_MEMORY_LIMIT.
  • URL сайта (иногда).

Пример содержимого:

<?php
define('DB_NAME', 'my_database');
define('DB_USER', 'my_user');
define('DB_PASSWORD', 'my_password');
define('DB_HOST', 'localhost');
define('DB_CHARSET', 'utf8mb4');
define('DB_COLLATE', '');

$table_prefix = 'wp_';

define('WP_DEBUG', false);
define('WP_MEMORY_LIMIT', '256M');

/* ... секретные ключи ... */

require_once ABSPATH . 'wp-settings.php';
⚠️ Осторожно с wp-config.php! Одна опечатка — и сайт перестанет открываться. Всегда делайте копию этого файла перед правкой. Если сайт «упал» после правки — восстановите файл из копии.

.htaccess — правила сервера

Файл .htaccess — это конфигурация веб-сервера Apache. Здесь настраиваются:

  • Постоянные ссылки (ЧПУ): красивые URL вида /o-nas/ вместо /?page_id=2.
  • Редиректы: перенаправления с одной страницы на другую.
  • Безопасность: блокировка доступа к определённым файлам.
  • Кэширование: правила для браузера.
  • Сжатие: gzip-сжатие для ускорения.

Типичный .htaccess для WordPress:

# BEGIN WordPress
<IfModule mod_rewrite.c>
RewriteEngine On
RewriteBase /
RewriteRule ^index\.php$ - [L]
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule . /index.php [L]
</IfModule>
# END WordPress
💡 Важно: Файл .htaccess начинается с точки — это скрытый файл. В FTP-клиентах и файловых менеджерах включите «Показывать скрытые файлы», иначе вы его не увидите.

index.php — точка входа

Корневой index.php — минимальный файл, который подключает WordPress:

<?php
define('WP_USE_THEMES', true);
require __DIR__ . '/wp-blog-header.php';

Трогать его не нужно — он отвечает только за запуск системы.

2.4 Три способа увидеть структуру файлов

Прежде чем работать с файлами, нужно научиться их просматривать. Есть три способа.

Способ 1: Файловый менеджер хостинга

  1. Войдите в панель управления хостингом (cPanel, ISPmanager, Beget).
  2. Найдите «Файловый менеджер» (File Manager).
  3. Откройте корневую папку сайта — обычно public_html, www или htdocs.
  4. Изучите структуру папок. Вы увидите все файлы WordPress.
  5. Включите показ скрытых файлов (в настройках файлового менеджера), чтобы увидеть .htaccess.

Способ 2: FTP-клиент (рекомендуется)

FileZilla — бесплатный FTP-клиент. Подключение разберём подробно в главе 3. Сейчас важно знать, что после подключения вы увидите ту же структуру папок, что и в файловом менеджере.

Способ 3: Встроенный редактор WordPress

  1. Войдите в админ-панель WordPress.
  2. Перейдите в «Внешний вид → Редактор файлов».
  3. Если пункта нет — значит, редактор отключён хостингом (это часто делают для безопасности).
  4. Если пункт есть — вы можете просматривать файлы темы и плагинов прямо в браузере.
⚠️ Осторожно с редактором файлов в админке! Если в файле есть синтаксическая ошибка, сайт мгновенно «упадёт». При этом вы не сможете вернуться в редактор, потому что админка тоже перестанет открываться. Используйте FTP — он позволяет редактировать файлы без риска «заблокировать» себя.

2.5 Практический пример: находим проблемный плагин

Давайте применим знания на практике. Ситуация: после установки нового плагина сайт перестал открываться.

Пошаговое решение

  1. Подключитесь к сайту по FTP (или откройте файловый менеджер хостинга).
  2. Перейдите в папку /wp-content/plugins/.
  3. Найдите папку последнего установленного плагина. Обычно это папка с самым свежим «Дата изменения».
  4. Переименуйте папку: добавьте _off в конце. Например, my-plugin → my-plugin_off.
  5. Обновите сайт в браузере. Если он заработал — вы нашли виновника.
  6. Вернитесь в админку WordPress. Перейдите в «Плагины» — проблемный плагин будет отключён.
  7. Удалите плагин через админку или переименуйте папку обратно, если хотите попробовать его настроить.
✅ Что вы сделали: за 2 минуты восстановили сайт без вызова специалиста. Именно для таких ситуаций нужно знать структуру файлов.

2.6 Практический пример: находим и правим .htaccess

Ситуация: после смены хостинга страницы сайта стали открываться с ошибкой 404, хотя сами страницы на месте.

Пошаговое решение

  1. Подключитесь к сайту по FTP.
  2. Включите показ скрытых файлов (в FileZilla: «Сервер → Показывать скрытые файлы»).
  3. Найдите файл .htaccess в корне сайта.
  4. Скачайте его на компьютер — сделайте резервную копию.
  5. Откройте файл в редакторе кода (VS Code, Notepad++).
  6. Проверьте содержимое. Скорее всего, он пустой или содержит неверные правила.
  7. Вставьте стандартные правила WordPress:
# BEGIN WordPress
<IfModule mod_rewrite.c>
RewriteEngine On
RewriteBase /
RewriteRule ^index\.php$ - [L]
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule . /index.php [L]
</IfModule>
# END WordPress
  1. Сохраните файл.
  2. Загрузите его обратно на сервер, перезаписав старый.
  3. Обновите сайт. Ошибка 404 должна исчезнуть.
💡 Совет: Если не уверены в содержимом .htaccess, зайдите в админку → «Настройки → Постоянные ссылки» и просто нажмите «Сохранить». WordPress автоматически пересоздаст файл с правильными правилами.

2.7 Что копировать при резервном копировании

Понимание структуры помогает правильно делать бэкапы. Вот что нужно копировать:

Что копировать Обязательно? Зачем
wp-content/ ✅ Да Темы, плагины, загрузки — всё уникальное содержимое сайта.
wp-config.php ✅ Да Настройки подключения к базе данных.
.htaccess ✅ Да Правила сервера, ЧПУ, редиректы.
База данных ✅ Да Записи, страницы, настройки, пользователи.
Ядро (wp-admin/, wp-includes/) ❌ Нет Скачивается заново с wordpress.org. Нет смысла копировать.
wp-content/cache/ ❌ Нет Временные файлы, воссоздаются автоматически.
wp-content/upgrade/ ❌ Нет Временные файлы обновлений.
💡 Практическое правило: Копируйте всё, кроме ядра. Это займёт меньше места и времени, а сайт восстановится полностью. Ядро всегда можно скачать заново.

2.8 Решение типичных проблем

Проблема Причина Решение
Не могу найти .htaccess Не включён показ скрытых файлов В FileZilla: «Сервер → Показывать скрытые файлы». В файловом менеджере — настройки.
Не вижу пункт «Редактор файлов» в админке Хостинг отключил редактор Используйте FTP или файловый менеджер хостинга.
Папка uploads/ занимает много места Много изображений и их миниатюр Оптимизируйте изображения, удалите неиспользуемые. Проверьте плагины, создающие лишние миниатюры.
Сайт «упал» после правки wp-config.php Синтаксическая ошибка Восстановите файл из резервной копии через FTP.
Не вижу папку темы Папка переименована или удалена Проверьте папку wp-content/themes/. Переустановите тему, если она удалена.
После обновления темы пропали правки Правки были в файлах темы Используйте дочернюю тему (глава 7) или «Дополнительные CSS» (глава 6).
Плагин не удаляется через админку Ошибка прав или повреждённая папка Удалите папку плагина через FTP или файловый менеджер.
Не могу подключиться по FTP Неверные данные или порт Проверьте данные в панели хостинга. Иногда нужно использовать SFTP (порт 22) или другой порт.

2.9 Практическое задание

📝 Задание для самопроверки

Часть 1: Изучение структуры
1. Войдите в панель управления вашим хостингом.
2. Откройте файловый менеджер.
3. Найдите корневую папку сайта (public_html, www или htdocs).
4. Изучите структуру: найдите wp-admin, wp-includes, wp-content.
5. Включите показ скрытых файлов.
6. Найдите wp-config.php и .htaccess.
7. Сделайте скриншот структуры (не открывайте содержимое важных файлов!).

Часть 2: Изучение wp-content
8. Откройте папку wp-content.
9. Найдите папку активной темы в themes/.
10. Изучите файлы темы: style.css, functions.php, theme.json.
11. Откройте папку plugins/ — посмотрите, какие плагины установлены.
12. Откройте папку uploads/ — посмотрите структуру по годам и месяцам.

Часть 3: Безопасное копирование
13. Скачайте файл wp-config.php на компьютер.
14. Откройте его в редакторе кода (VS Code, Notepad++).
15. Найдите строки с DB_NAME, DB_USER, DB_HOST.
16. Сохраните их в надёжном месте (в менеджере паролей).
17. НЕ вносите никаких изменений.

Часть 4: Диагностика
18. Откройте папку plugins/.
19. Найдите плагин, который вы не используете.
20. Если решите его удалить — сначала деактивируйте через админку.
21. Только потом удаляйте папку.

Часть 5: Финальная проверка
22. Убедитесь, что сайт работает.
23. Проверьте, что резервная копия wp-config.php сохранена.
24. Запишите структуру папок — она понадобится в следующих главах.
✅ Что вы освоили: Общую структуру файловой системы WordPress; назначение каждой папки и ключевых файлов; разницу между ядром, контентом и конфигурацией; работу с wp-config.php и .htaccess; три способа просмотра файлов; поиск проблемного плагина; правила резервного копирования; решение типичных проблем.

2.10 Часто задаваемые вопросы

  • Можно ли удалить папки wp-admin и wp-includes? Нет. Это ядро WordPress. Без них сайт не будет работать.
  • Что делать, если я случайно удалил файл из ядра? Скачайте WordPress заново с wordpress.org, распакуйте и загрузите отсутствующие файлы по FTP. Не загружайте wp-config.php из архива!
  • Как узнать, какая тема активна? В админке: «Внешний вид → Темы». Активная тема помечена. Или по папке wp-content/themes/ — там может быть несколько тем, но активна одна.
  • Можно ли переименовать папку wp-content? Да, но для этого нужно изменить константу WP_CONTENT_DIR в wp-config.php. Обычно в этом нет необходимости.
  • Как найти плагин, который нагружает сайт? Просмотрите список плагинов в админке. Отключайте по одному и проверяйте скорость. Или используйте плагин Query Monitor.
  • Где хранится база данных? Не в файлах. База данных хранится на сервере MySQL и управляется через phpMyAdmin. Доступ к ней — через данные в wp-config.php.
  • Как перенести сайт на другой хостинг? Скопируйте wp-content/, wp-config.php, .htaccess и экспортируйте базу данных. На новом хостинге загрузите файлы, создайте базу, импортируйте дамп, настройте wp-config.php.
  • Что такое mu-plugins? Это «must-use» плагины — они загружаются автоматически и не могут быть отключены. Часто используются хостингами для служебных функций.
